# Agent Team 接班与读取路由设计

> 目标:让默认路径保持简单。四份现有文档负责接班,脚本只处理确定性的元数据定位和单文件局部提取;上下文状态恶化时换会话,不叠加检索状态机。

## 四文档是真相源

新会话按固定顺序读取:

1. `上岗引导.md`:接班、交班、换会话入口。
2. `岗位说明.md`:长期职责、边界、输入输出和可写范围。
3. `交接班文档.md`:进行中、下一步、已定决策、已知坑和关键文件。
4. `收件箱.md`:未领取待办和任务详情真相源。

不要让脚本再次汇总这四份文件,也不要创建第五份接班文档。岗位说明和上岗引导保持稳定;交接班文档覆盖更新;收件箱处理即清。

## 局部信息提取

不使用固定字数定义“长文”,因为 Agent 通常无法可靠得知当前会话剩余上下文。只判断任务是否需要理解全文:

- 需要理解整份契约、Spec、决策或完整上下文:直接读原文。当前会话已压缩、偏离职责或质量下降时,先交班换会话。
- 只需要已知文件中的一个事实、主题或段落:运行一次 `agent_team_read.py search`。
- 命中片段已经回答问题:停止。
- 命中位置明确但需要更完整连续段落:再运行一次 `slice`。
- 术语未知、跨文件关系复杂或完整性要求高:不要连续扩词调用脚本;选择必要原文完整读取、换新会话承载,或明确未验证项。

脚本保留路径边界、符号链接拒绝、UTF-8 编码检查、扫描上限和单次输出保险丝。保险丝只防异常输出,不证明证据充分。

## 报告元数据

`meta/find` 只读取人工填写的受限单行字段,用于定位报告、审核报告、专项结论和关键决策。脚本不读正文后创造性总结,不替代统筹或审核判断。

## 同部门一键换班

用户说“换会话 / 切换会话 / 换班”时:

1. 旧会话先更新交接班文档和必要日志。
2. 从部门表取得已登记旧会话 ID。
3. 使用原生会话工具创建同项目本地新会话;不要 fork 旧聊天历史。
4. 向新会话发送部门名、新旧会话 ID 和四文档路径。
5. 新会话接班成功后,只更新部门表中本部门这一行的“会话 ID / 状态”;不得改其他字段或部门。
6. 登记成功后再归档旧会话;任一步失败都保留旧会话并报告真实状态。工具不全时使用会话启动清单中的固定手动回退模板。

## 默认不读

- 全量日志正文。
- 与当前任务无关的报告、决策和其他部门正文。
- 大段代码 diff 和测试证据全文。
- 已完成节点的历史聊天。

需要上述内容时,优先读取当前任务明确指向的最小必要范围;如果任务本身要求整体理解,直接换到干净会话承载,不要继续给旧会话叠加工具输出。
