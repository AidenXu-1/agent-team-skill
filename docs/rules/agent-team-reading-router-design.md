# Agent Team 读取路由优化清单

> 目的:把多会话协作的阅读边界从“靠 Agent 自觉”改成“裁剪接班包 + 两级检索 + 候选账本 + 覆盖报告”。硬输出预算只防失控,不作为证据完整性的替代品。

## 会话模式

- 只保留两种模式:自动模式 / 人工模式。
- 自动模式:Agent 具备创建会话、命名会话、发送短唤醒的会话管理能力。
- 人工模式:Agent 不声称已通知其他部门;只写目标部门收件箱,并提醒用户手动通知对应部门。
- 置顶、排序不是必要能力,不作为模式判断条件。

## 上岗引导

- `上岗引导.md` 是轻量常态化路由卡,不是长制度手册。
- 它只说明当前部门身份、层级、先运行哪个读取脚本、默认读什么、默认不读什么、自动/人工通知方式。
- 长规则放在共享规则文档、岗位说明、收件箱模板和报告模板中,不要在每个上岗引导里重复堆叠。

## 读取路由脚本

- scaffold 生成 `docs/collaboration/scripts/agent_team_read.py` 和 `agent_team_research.py`。
- 两个脚本都是确定性读取路由器,不是管理大脑,不调用模型。
- `agent_team_read.py` 只做稳定裁剪:
  - 根据部门名返回身份、层级、通知模式、会话 ID。
  - 直接返回裁剪后的岗位核心、交接摘要、统筹部项目进度和最新 1-5 条待办正文;来源文件只作为指针,不要求 Agent 再全文读取。
  - 读取受限单行元数据,返回 `summary` 等人工预写字段。
  - 按 `type`、`department`、`target`、`status`、`tags` 查候选文件。
  - `search` 在单个长文中只返回带行号的命中片段,`slice` 只返回指定行范围。
  - 每次调用有字段、文件、扫描字节、单行、切片行数和终端输出上限;截断必须显式显示。
- `agent_team_research.py` 只在跨文件、未知原词、证据分散或遗漏代价高时启用:
  - AI 先冻结用户原问题,最多增加 12 个同义词、实体名、上下位概念、限制条件、失败模式和反证词;扩词不能替换原问题,每个扩词只放一个短词或短语。
  - 脚本按 Markdown 标题和字符边界切块,使用中文安全词法特征、逐查询配额和类似 RRF 的融合排序;第一版不引入向量数据库。
  - 完整候选、来源哈希、文件范围和截断状态保存在 `.retrieval/<task-id>/manifest.json`;AI 可分组/重排,不得永久删除候选。
  - `pack` 只输出 AI 选择的有界证据包并保留引用;未选候选仍留在 manifest。`target-tokens` 是软目标,不是完成条件。
  - `coverage` 显示扫描文件/字节/格式/候选配额;覆盖不足时最多允许一轮带限制、失败和反证词的补检,之后必须写未验证项或拆任务。
- 脚本不做创造性总结、不替代统筹判断、不替代审核结论、不自动放行,也不宣称检索绝对完整。

## 受限单行元数据

- `---` 分隔符只借用 YAML 外形,实际是受限单行字段协议,不宣称支持完整 YAML。
- 只允许固定字段;重复键、未知字段、多行值、超长值、非 UTF-8 元数据直接拒绝。
- 报告、审核报告、专项结论、关键决策都使用统一基础字段:

```yaml
---
type: audit_report
department: 测试部
target: IndexTTS2分段生成
status: blocked
date: 2026-07-02
related_task: 测试部收件箱#2026-07-02-001
decision: 不通过
tags: [用户可见出口, 错误文案, worker, UI]
summary: 用户最终错误文案丢失段号，底层通过不代表出口通过。
---
```

`type` 可用值:

- `work_report`
- `audit_report`
- `special_conclusion`
- `decision_record`

## 报告体系

- 不是所有部门都必须产出正式报告。
- 所有部门默认维护收件箱回报、交接班文档、日志索引和必要产出路径。
- 审核层必须产出审核报告。
- 执行层只有遇到复杂研究、设计、方案、架构、数据分析时才产出工作报告。
- 统筹部只有需要阶段总结、决策材料、用户判断材料时才产出报告。
- “把关报告”在规则中统一解释为审核层报告;目录可兼容旧名,模板标题应写“审核报告”。

## 专项结论

- 只影响一个任务、一个部门:放在对应报告正文。
- 会被多个部门复用:升格到 `docs/collaboration/专项结论/`。
- 长期改变项目规则、架构、依赖、安全或发布方式:升级到 `docs/decisions/`。

## 默认阅读边界

- 默认读:上岗引导和 `onboard` 返回的裁剪接班包。岗位说明、交接班和收件箱默认不再全文读取。
- 按需读:错题集的当前任务相关条目、`search` 命中后的最小 `slice`。
- 默认不读:日志正文、报告正文、决策正文、其他部门正文、代码 diff、测试证据全文。
- 触发才读正文:接班包截断、摘要不足、路径异常、结论冲突、涉及放行/返工/安全/费用/发布/用户可见质量、用户要求查证据、当前任务明确依赖正文。

## AI 与脚本的职责边界

- AI 擅长理解意图、提出查询扩展、判断候选与问题的关系、综合与写出未验证项。
- 脚本擅长固定路径边界、切块、去重、配额、融合、字节/token 软预算、来源哈希、账本和可复现输出。
- AI 的“无关”只是当前排序标签,不是删除许可;脚本的“零命中”只是本轮查询结果,不是“不存在”的证明。
- 最优策略不是规定死总 token,而是同时保留单次硬保险丝、可调证据包软目标、覆盖报告和一次反证补检。
- 上线向量检索前必须先建立离线 gold set,用召回率、证据覆盖率、引用正确率、上下文 token 和延迟做 A/B;没有数据不得假设向量方案更全。

## 进度与决策

- `docs/progress.md` 是项目级总状态,由统筹部维护。
- 统筹部接班默认读;新增部门/新会话上岗、任务背景不足、用户问整体进度、阶段切换、收口、发布前、多部门冲突时才读。
- 执行层和审核层平时不默认读 `docs/progress.md`。
- 重大技术决策双写但不重复正文:部门日志写一行索引,`docs/decisions/` 写正式决策正文。
