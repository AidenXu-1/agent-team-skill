# Agent-Team 2.1.0 候选简易升级报告

> 一句话结论：这次升级已经把“靠 Agent 自觉遵守”推进为“关键错误会被状态机拦住”，首次接班的实测输入 Token 平均下降 40.5%、工具调用下降 60%；但长期会话总成本、真实 Lulu 体验和公开发布仍不在本次 PASS 范围内。

## 本次比较对象

- 旧全局运行版：Agent-Team 2.0.11，协议 1.4.15。
- 当前源码候选：Agent-Team 2.1.0，协议 1.5.0。
- 候选身份：`AT-2.1.0-RC-7711517262CE`。
- 候选五文件运行集 SHA-256：`7711517262ce6f1b1d3445f873784636b78406ffb717a467a8753dcf1f9d6517`。
- 公开 Latest：2.0.6。本报告不改变公开版本、全局安装版或任何项目协议。

## 过去的问题与实际提升

| 过去的问题 | 2.0.11 的主要缺口 | 2.1.0 候选的改进 | 提升结论 |
|---|---|---|---|
| 开发体验差、TASK 越返工越多 | 单切片和原 TASK 返工主要依赖规则约束 | 全项目一个活动切片、一个 owner、最多两个 gate；返工更新同一 owner 的候选代次 | 从提示约束升级为机械状态门，定性明显提升 |
| 热上下文和 Token 过重 | 新会话分多次读取热入口，宿主往返较多 | `onboard-bundle` 一次校验 freshness，只输出岗位、交接、收件箱和当前 TASK，不展开冷历史 | 首次接班输入平均下降 40.5%，工具调用下降 60% |
| 普通 TASK 身份漂移 | 曾能用未登记或过期会话身份操作普通 TASK | claim、block、wait、resume、complete 绑定当前已登记部门会话；换班后先 rebind | 从已复现的失败开放改为失败关闭 |
| 局部 PASS 冒充可用 | TASK 状态、业务质量、用户授权容易混写 | 执行状态、业务阶段、授权状态分轴；gate 必须绑定同一候选并提交最终审核报告 | 局部 PASS 不再能直接替代产品、用户或发布出口 |
| 候选重复或审核串线 | 候选身份和返工代次约束较弱 | 候选 ID 全项目唯一，manifest 和产物 SHA 绑定；两个 gate 只审同一代候选 | 旧候选复用、错候选 verdict 和证据漂移均被反向探针阻断 |
| 连续失败继续膨胀 | 冻结规则缺少完整原子状态闭环 | 同一 gate 跨两代连续 FAIL 自动冻结；崩溃后事务恢复使 TASK 与冻结状态收敛 | 从事后提醒升级为机械止损 |
| 热交接过期、冷历史污染 | 交接文字、收件箱和 TASK 真值可能漂移 | hot-state/freshness 校验、活动索引与 legacy 冷索引分离；篡改后接班失败关闭 | 日常读取不再依赖展开全部历史 |
| 不知道何时换会话 | 只有泛化的“会话变重”提醒 | 统筹按阶段、执行按切片；同切片返工续用。旧候选串入、重复读取和压缩后很快失焦才建议换班 | 固定三场景规则评分由 2/3 提升到 3/3；这是语义评分，不是 Token 实测 |
| 宿主能力被 Skill 口号代替 | heartbeat、lease、等待与归档边界不够醒目 | 缺宿主适配器时明确 `manual-degraded`，不轮询、不承诺无人值守 | 主要提升是避免虚假承诺，宿主能力本身尚未新增 |
| 存储压力 | 冷历史持续保留 | 冷历史从热路径移出并保留审计；没有自动删除 | 降低日常读取压力，物理存储占用没有被证明下降 |

## Token 与工具调用实测

测试固定 `gpt-5.6-sol`、低推理、同一提示、同一合成项目和交替顺序；旧版与候选各 2 次，只测首次接班。

| 指标 | 2.0.11 | 2.1.0 候选 | 观察变化 |
|---|---:|---:|---:|
| 平均输入 Token | 137,668 | 81,903.5 | -40.5% |
| 平均缓存输入 | 106,496 | 51,712 | -51.4% |
| 平均输出 Token | 616.5 | 348 | -43.6% |
| 平均推理输出 | 148.5 | 91 | -38.7% |
| 平均工具调用 | 5 | 2 | -60.0% |
| 热入口字节 | 5,703 | 6,257 | +9.7% |

两组配对输入降幅分别为 50.5% 和 25.4%，平均 40.5%。这说明主要收益来自减少宿主往返，并非通过删掉当前任务信息或缩短规则制造数字。

限制必须保留：每侧只有 2 次样本，使用合成项目；没有测试继续旧会话、压缩后继续、精简交接新会话的完整生命周期，也没有测量价格、Lulu 真实任务质量或前台体验。

## 最终关键验证

- 旧全局 2.0.11 的五个运行文件与仓库不可变 fixture 逐字节一致，运行集 SHA-256 均为 `171fae3f6cae4454a4cca5521a894e615431e323180d0344b7b2cf3eda4a28ec`。
- 正确 fixture 入口实跑得到 `LEGACY_2011_MIGRATION_OK | task_bytes_preserved=true`。
- 完整验证得到 `VERIFY_OK`，覆盖登记身份、单 slice/owner/最多两 gate、候选代次、连续失败冻结、freshness、冷索引、迁移/回滚、统一锁竞态、路径保护、manual host boundary 和有界历史。
- 固定会话生命周期三场景：旧版 2/3，候选 3/3。新增通过项是“无可比宿主数据时必须写无法测量，禁止用固定倍数自动换会话”。

保留一条无效测试样本：首次把 `AGENT_TEAM_LEGACY_2011_ROOT` 错指向只有五个运行文件的全局安装目录，验证器因缺测试专用 `fixture-manifest.json` 退出。该变量的正确合同是不可变测试 fixture；逐字节确认 fixture 等于全局五文件后重跑通过。因此它是测试入口错误，不计为候选缺陷，也没有通过放宽验证器掩盖。

## 结论边界与后续

- P0：本次源码候选关键比较未发现剩余 P0，可进入提交门。
- P1：若要宣称“整个长期会话更省 Token”，还需真实项目的小规模生命周期 A/B，对比继续旧会话、压缩后继续和精简交接新会话。
- P2：heartbeat、lease、等待、恢复、归档和第二执行者仍需要 Codex 宿主适配；当前保持 `manual-degraded`。
- 发布边界：Commit 不等于发布。后续仍需远端 CI、绑定审查 commit 与运行集 SHA、fresh clone、版本化纯运行包、公开后重新下载与 Latest 验真。
- 升级边界：本轮不更新全局 Skill，不升级 Lulu，不修改任何 Lulu 业务、App、Keychain、安装器或用户数据。

最终比较结论：`FINAL_COMPARISON_PASS`。
