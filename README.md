> **当前正式版：2.1.0 · 适用于 Codex**

Agent Team 是一个适合长期开发项目的 开发Skill。

你只需要把需求告诉统筹会话。它会安排合适的执行和审核会话，把重要进度保存在项目资料里。即使以后换了新会话，也能从当前进度继续，不用每次重新解释整个项目。

## 安装提示

把下面整段话发给 Codex：

```text
请打开下面的 Agent Team 最新版页面，只下载安装标记为 Latest 的正式版本。安装前核对随包提供的校验文件，安装到我的 Codex 全局 Skill 目录。安装完成后告诉我实际安装版本，不要修改任何项目：
https://github.com/AidenXu-1/agent-team-skill/releases/latest
```

安装完成后，在你准备长期使用的项目会话中发送：

```text
请使用 Agent Team。先了解这个项目，根据目标给我建议最少需要哪些部门，并用大白话说明各自负责什么。先把方案给我看，等我确认后再创建团队。
```

## 怎么使用

1. **你提出目标**
   例如“帮我完成这个 App”“把这个功能修到可以真实体验”或“长期运营这个内容项目”。

2. **它先建议团队**
   Agent Team 会根据项目需要给出最小团队，不会为了显得复杂而创建一堆部门。你确认后才会正式搭建。

3. **专人干专活**
   各部门分工协作，只干属于自己分内的事。统筹负责安排，执行负责做，审核负责查，谁也不越权。

4. **该你出手时才找你**
   需要体验、选方向、补资料或确认发布时，统筹会把事情说清楚。纯代码检查由团队内部完成，不用事事等你点头。

5. **压力大就换班**
   会话开始记混、反复翻旧资料时，统筹会先问你要不要换。你同意后，新会话带着现有进度接手，前面的工作不用重来。

6. **并行任务招外包**
   遇到能和主线分开的独立任务，可以先让统筹看看能不能外包。能安全并行，就交给临时会话单独做，做完回原部门检查；条件不够就直说，不会硬开。

## 快捷指令

不需要记复杂格式，直接在统筹会话里说下面这些话就可以：

| 你直接说 | 它会做什么 |
|---|---|
| **`接班`** | 读取自己的职责、最新交接和当前工作，恢复到正确状态 |
| **`先接班，不要开始任务`** | 完成接班并向你汇报当前情况，然后停下来等你 |
| **`交班`** | 更新最新进度、决定和待办，为后续接班做好准备；不会自动换会话 |
| **`换班` / `换会话`** | 为同一个部门建立新会话；新会话确认接班后，旧会话才退出 |
| **`汇报进度`** | 只告诉你做到哪里、有什么风险和下一步，不改变当前工作 |
| **`先回答问题，不要改变当前任务`** | 先回答你的临时问题，原来的工作保持不变 |
| **`继续当前任务`** | 临时问答或等待结束后，回到原来的工作继续推进 |
| **`这件事适合外包吗？`** | 只判断是否适合交给临时会话处理，不等于授权创建 |
| **`外包` / `临时外包`** | 让统筹检查能否把一件边界清楚的工作交给临时会话；当前环境不能安全创建第二个执行会话时，会直接说明限制，主线保持不变 |

外包只针对一件边界清楚的工作，不会变成一个长期部门，也不会因为一句询问就擅自创建。

### 它会怎样向你汇报

正式节点默认使用“结果 / 需要你做什么 / 还需注意”：

- **结果**：这一步完成了什么，现在能不能用。
- **需要你做什么**：无需操作、需要你判断，或需要你按步骤体验。
- **还需注意**：真正会影响决定的风险或限制；没有就不硬凑一段。

普通问答不会套模板。你临时问一个问题，它会直接回答；只要没有改变原来的目标，就不会打断正在做的事。

## 协作资料为什么这样设计

创建团队后，Agent Team 会在项目里建立一个协作资料文件夹。目的很简单：把不同性质的信息分开保存，让新会话只读眼前真正需要的部分。

| 资料 | 用来保存什么 | 为什么单独设计 |
|---|---|---|
| **部门表** | 项目有哪些部门、各部门由哪个会话负责、现在是否已经上岗 | 防止会话认错身份，也让统筹知道任务该交给谁 |
| **岗位说明** | 一个部门长期负责什么、不负责什么、能改哪些内容、哪些决定必须交还给用户 | 防止聊久以后职责悄悄变化，或者一个部门越权替别人做决定 |
| **上岗引导** | 新会话第一次接班时的阅读顺序和必要入口 | 让新会话从正确位置开始，不用自己翻找整段历史；同一会话只需使用一次 |
| **交接班文档** | 已做到哪里、关键结论、下一步、已知问题和重要文件位置 | 换会话时带走真正有用的施工现场，不把整段聊天重新搬过去 |
| **收件箱** | 当前待领取、正在处理或受阻的工作索引 | 让每个部门快速看见眼前的工作；它会随任务自动更新，不拿手工留言冒充正式任务 |
| **任务记录** | 每件工作的要求、负责人、当前状态、验收条件、产出和完成证据 | 同一件事只保留一份正式记录，避免收件箱、交接和聊天各说一套 |
| **错题集** | AI 曾经犯过、以后可能再犯的错误，以及正确做法 | 相关任务开始或结束时定向检查，减少重复踩坑；普通的一次性小问题不会全部塞进去 |
| **日志** | 真正改变项目进程的节点、需求变化、用户纠正、重要决定和事故 | 留下可追溯的事实，同时避免把普通回复、工具过程和完整聊天堆成历史包袱 |
| **报告** | 复杂工作的正式成果，以及审核部门亲自取得的检查结论和证据 | 让“已经做完”和“已经检查通过”分开；普通小任务不强制写长报告 |

这些资料刻意回答不同的问题：部门表回答“谁在做”，任务记录回答“现在做什么”，交接班文档回答“做到哪里”，日志回答“发生过什么”，报告回答“真正检查过什么”。这样既能长期接着做，也不容易把旧信息误当成当前状态。

## 适合什么项目

**适合：**

- 产品功能较多、逻辑复杂、需要长期维护的中大型开发项目
- 愿意降低一定的效率换更高的质量
- 在意真实体验、独立验收和过程可追溯

**可以不用：**

- 功能较少或逻辑简单，不需要商业交付的自用小工具
- 不需要分工、接班和独立审核的单步骤工作
- 一次问答、一段短文或很快能结束的小任务
- 效率要求极高、项目开发周期特别短

## 必要说明

- Agent Team 主要为 Codex 设计，其他不具备会话线程管理工具的Agent需要手动创建会话并在交接过程中对对应部门进行简要提醒，任务安排仍可通过后台收件箱进行发放。
- 创建团队前会先给出方案并等待你确认，不会因为安装完成就自动修改项目。
- 启用后会在项目内创建一个协作资料文件夹，用来保存职责、进度、交接和审核结果。
- 产品体验、方向、发布、费用、隐私和安全决定仍然由你确认。
- Agent Team 自带脚本不会主动联网或上传项目内容；Codex 如何处理内容，取决于你使用的服务和隐私设置。
- 它能减少无关历史进入当前工作，但不会承诺所有项目都按固定比例节省用量。
